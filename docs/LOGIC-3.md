## 9. الميزانية العمومية — `buildBalanceSheet(asOf)` (module-reports.js)

### 9.1 المكونات
```
cash     = رصيد الخزينة (vault) حتى تاريخ asOf
bank     = رصيد البنك حتى asOf
network  = رصيد الشبكة (مدى/بطاقات) حتى asOf
receivables = الذمم المدينة (قسم 9.4 تحت)
bagInventory = قيمة مخزون الحقائب المتبقي = الكمية المتبقية × سعر الحقيبة الحالي في الإعدادات
fixedAssetsNet = إجمالي الأصول الثابتة (من قيود يدوية) − مجمع الإهلاك (من قيود يدوية)
```

### 9.2 التزام أمانة الحقائب (bagCustody) — **أهم بند في الميزانية**
```
bagCollected = مجموع bagAmount(c) لكل العملاء غير الموقوفين حتى asOf
             // كل المبالغ اللي اتحصّلت من العملاء مقابل حقائب

stockIssued  = عدد العملاء اللي أخذوا حقيبة من المخزون (bagSource='stock')
spentDirect  = مجموع bagPrice للعملاء اللي المركز اشترى لهم حقيبة مباشرة (bagSource='buy', bagStatus='purchased')

bagCustody = bagCollected - (stockIssued × سعر_الحقيبة_الحالي + spentDirect)
```
**التفسير**: الفرق بين "اللي اتحصّل من العملاء" و"اللي فعلاً اتصرف/اتسلّم" = **التزام** على المركز (أمانة لسه ما اتسلمتش/اتصرفتش). لو النتيجة سالبة (نادر — يعني اتسلّم أكتر مما اتحصّل)، النظام بيعرضها كـ **أصل** بدل التزام سالب (مش منطقي محاسبياً تفضل سالبة).

### 9.3 المعادلة الكاملة
```
totalAssets = cash + bank + network + receivables + bagInventory
              + max(0, fixedAssetsNet) + bagCustodyAsset   // لو bagCustody سالب
              + manualSalesAR                               // ذمم المبيعات اليدوية المرحّلة (§9.6)

totalLiabilities = max(0,bagCustody) + max(0,loans) + accrued + otherLiab
                   + accountsPayable + vatPayable           // من دفتر اليومية (§9.6)

totalEquity = totalAssets - totalLiabilities
retainedEarnings = رصيد حساب 3100 الصريح + صافي الدخل المتراكم حتى asOf
ownerCapital = totalEquity - retainedEarnings   // رأس المال = حقوق الملكية − الأرباح المرحّلة
```

### 9.4 الذمم المدينة (Receivables)
```
receivablesAsOf(asOf) = مجموع max(0, total(c) - paidTotalAsOf(c, asOf))
                         لكل عميل غير موقوف وغير ملغي، تاريخه ≤ asOf
```

### 9.5 القروض (تصنيف تلقائي بالكلمات المفتاحية!)
```
loansPayableAsOf(asOf):
  حركات الخزينة غير المرتبطة بعميل وغير مرتبطة بمخزون حقائب،
  واللي isLoanTx(t) = true  ← ده بيتحدد تلقائياً من فحص كلمة "قرض" في ملاحظات/تصنيف الحركة
  = (مجموع الوارد "in") - (مجموع الصادر "out")
```
> **ملاحظة تصميم مهمة لـ FTC4**: القروض حالياً بتتحدد بالنص (regex على كلمة "قرض") مش بحقل مخصص. في إعادة البناء، الأفضل يبقى فيه `type: 'loan'` صريح بدل الاعتماد على تحليل النص — أدق وأسهل صيانة.

### 9.6 البنود المُرحّلة من دفتر اليومية (توازن الميزانية مع ميزان المراجعة)
```
manualSalesAR  = رصيد حساب 1100 (ذمم عملاء) من قيود المصدر sourceManualSaleId فقط حتى asOf
                 // ذمم الدورات محسوبة أصلاً في §9.4 من جدول العملاء — القيود دي هنا لتفادي الخصم المزدوج
accountsPayable = رصيد حساب 2000 (ذمم موردين) من قيود المصدر sourcePurchaseId حتى asOf
vatPayable      = رصيد حساب 2100 (ضريبة مستحقة) صافي كل القيود حتى asOf
retainedEarnings = رصيد 3100 الصريح + صافي دخل قائمة الدخل (من بداية النشاط حتى asOf)
```

> **التوازن مع ميزان المراجعة:** بإضافة بنود §9.6، تصبح الميزانية العمومية تطابق
> أرصدة حسابات الميزانية (1100/2000/2100) في ميزان المراجعة، والأرباح المرحّلة
> تمثّل صافي الدخل المتراكم — فتنطبق `الأصول = الخصوم + حقوق الملكية` على نفس
> القيود التي يبني عليها ميزان المراجعة.

## 10. قائمة التدفقات النقدية (Cash Flow) — الطريقة المباشرة

```
لكل حركة خزينة/بنك/شبكة (باستثناء destination='other') ضمن الفترة:

  لو type='in':
    - تُتجاهل تماماً لو !vaultTxCountsTowardBalance(t)  // حركات واردة غير مُسوّاة بعد
    - لو مرتبطة بعميل (clientId) أو بحوالة شركة (companyTransferId) → تشغيلي (opIn)
      // حوالة الشركة عمداً بتتحسب تشغيلي رغم إنها مالهاش clientId مباشر — لأنها إيراد حقيقي
      // من عميل (شركة)، بس ممثّلة كقيد واحد لعدة متدربين
    - غير كده → تمويلي (finIn)  [تبرعات/دعم رأس مال/قروض واردة]

  لو type='out':
    - لو مردود (isReturn) → opReturns
    - لو تصنيفها مالي (تحتوي: مسحوبات/شركاء/قرض/رأس مال) → finOut
    - لو تصنيفها استثماري (تحتوي: أصل/أصول) → invOut
    - غير كده → opOut (تشغيلي عادي)

netOperating = opIn - opReturns - opOut
netInvesting = -invOut
netFinancing = finIn - finOut
netChange    = netOperating + netInvesting + netFinancing

beginCash = رصيد (خزينة+بنك+شبكة) في نهاية اليوم قبل بداية الفترة
endCash   = رصيد (خزينة+بنك+شبكة) في نهاية الفترة

فحص تطابق: expected = beginCash + netChange
            لازم يساوي endCash تماماً — أي فرق معناه فيه خلل في التصنيف
```

## 11. أعمار الذمم (Aging) — AR & AP

### 11.1 نظام الفئات (موحّد بين المدين والدائن)
```
agingBucket(days):
  0-30 يوم   → "0–30 يوم"
  31-60 يوم  → "31–60 يوم"
  61-90 يوم  → "61–90 يوم"
  90+ يوم    → "أكثر من 90 يوم"
```

### 11.2 الذمم المدينة (AR Aging) — `buildARAging`
```
لكل عميل غير موقوف وغير ملغي وله رصيد متبقٍ (> 0):
  dueDate = لو عميل شركة وله أجل ائتماني (creditDays>0):  تاريخ التسجيل + عدد أيام الأجل
            غير كده: تاريخ التسجيل نفسه (يعني مستحق فوراً، مفيش أجل)
  days = الفرق بين dueDate و asOf (تاريخ الاستحقاق كمرجع، مش تاريخ التسجيل)
```
**ملاحظة مهمة**: عملاء الشركات ليهم "أجل ائتماني" (زي 30/60 يوم) بيتحسب منه تاريخ الاستحقاق الفعلي — فمتدرب مسجل من 20 يوم لشركة أجلها 30 يوم لسه "في الأجل" (0 يوم تأخر)، مش متأخر 20 يوم.

### 11.3 الذمم الدائنة (AP Aging) — `buildAPAging`
```
كل فواتير المشتريات (purchases) بحالة "غير مسددة" (status='unpaid') وتاريخها ≤ asOf
days = الفرق بين تاريخ الفاتورة و asOf مباشرة (مفيش مفهوم "أجل" هنا، من تاريخ الفاتورة على طول)
```
