# FTC2 → FTC4: توثيق المعادلات والمنطق المحاسبي (الجزء 1)

> هذا المستند مستخرج مباشرة من كود FTC2 الفعلي (frontend/js/*.js) — مش من الذاكرة أو الافتراض.
> كل معادلة هنا لازم تُراجَع وتتأكد إنها فعلاً المنطق الصحيح قبل ما نبنيها في FTC4.
> ده الجزء الأول ويغطي: الأدوات الأساسية، الخزينة، تمويل الحقائب (أمانة)، حوالات الشركات.
> باقي الموديولات (الفواتير، ZATCA، التقارير المالية الكاملة) هتتوثق في أجزاء تالية.

---

## 1. الأدوات الأساسية (core-utils.js / undo-redo.js)

### 1.1 قراءة الأرقام `num(v)`
بيحوّل أي قيمة مُدخلة (نص، رقم، فاضي) لرقم صحيح بأمان:
- يحوّل الأرقام العربية-الهندية (٠١٢٣٤٥٦٧٨٩) والفارسية (۰۱۲۳...) لأرقام إنجليزية
- يحوّل الفاصلة العشرية العربية (٫) لنقطة عشرية إنجليزية
- يشيل فواصل الآلاف (٬ أو ,) قبل التحويل — عشان `parseFloat("1,000")` من غير المعالجة دي بترجع 1 بس (مش 1000)، وده كان بيسبب أخطاء مالية فادحة (المبلغ بيتسجل أقل بألف مرة)
- أي قيمة فاضية أو NaN → صفر

### 1.2 تنسيق العرض `fmt(n)`
`n.toLocaleString('en-US', {maximumFractionDigits: 2})`

### 1.3 ضريبة القيمة المضافة
```
const VAT_RATE = 0.15   // 15% ثابتة

vatFromGross(g) = num(g) - (num(g) / (1 + VAT_RATE))   // استخراج قيمة الضريبة من مبلغ شامل الضريبة
netFromGross(g) = num(g) / (1 + VAT_RATE)               // استخراج الصافي (بدون ضريبة) من مبلغ شامل الضريبة
```

### 1.4 التفقيط (تحويل المبلغ لكتابة بالحروف عربي)
دالة `numberToArabicWords(amount)` — منطق كامل:
1. تقريب المبلغ لأقرب هللة: `Math.round((amount + Number.EPSILON) * 100) / 100`
2. فصل الريالات عن الهلالات: `riyals = Math.floor(amount)`, `halalas = round((amount - riyals) * 100)`
3. لو `halalas >= 100` (تقريب حواف) → يترحّل هللة لريال إضافي ويتصفّر
4. تحويل كل رقم صحيح (بالتذكير أو التأنيث حسب الفئة) عبر تقسيمه لمجموعات ثلاثية (آحاد/عشرات/مئات) ثم مضاعفات الألف (ألف/آلاف، مليون/ملايين، مليار/مليارات) — مع تفرقة صيغة المثنى (ألفان) عن الجمع (آلاف) حسب العدد
5. الصياغة النهائية: `"فقط [كتابة الريالات] ريال سعودي و[كتابة الهلالات] هللة لا غير"`
6. لو المبلغ سالب: تُضاف كلمة "سالب" في البداية

> **ملاحظة مهمة لـ FTC4**: الدالة دي لازم تتترجم لنسخة إنجليزية مماثلة (`numberToEnglishWords`) بما إن الواجهة هتبقى ثنائية اللغة — لازم أتأكد منك هل الفاتورة الرسمية (ZATCA) لازم تفضل تفقيط عربي بس (زي ما هو مطلوب قانونياً غالباً)، والتفقيط الإنجليزي يبقى للعرض في الواجهة بس.

## 2. الخزينة والترقيم الرسمي (accounting-core.js)

### 2.1 الترقيم التسلسلي لكل وجهة على حدة
كل حركة خزينة ليها `seq` (رقم تسلسلي) **مستقل لكل وجهة** من الأربعة: `vault` (كاش) / `bank` / `network` / `other`. يعني حركة رقم 5 في "الكاش" مش لها علاقة برقم 5 في "البنك" — كل وجهة تبدأ ترقيمها من 1 وتزيد لوحدها.

```
allocVaultSeq(destination):
  1. تحديد الوجهة (افتراضي: vault لو مش من القيم الأربعة المعروفة)
  2. جمع كل الأرقام المستخدمة فعلاً لنفس الوجهة (من الحركات الفعّالة + المحذوفة منطقياً)
  3. البحث عن أول رقم "حر" بدءاً من settings.nextVaultSeqByDest[dest]
  4. لو الرقم المتوقع مستخدم بالفعل (حصل تعارض بسبب استعادة نسخة قديمة مثلاً) → نزود لحد ما نلاقي رقم فاضي
  5. تحديث العداد للرقم التالي، وإرجاع الرقم المستخدم
```

**قاعدة صارمة**: الرقم الرسمي لا يُعاد استخدامه أبداً حتى لو الحركة اتحذفت — عشان الأرقام دي بتتطبع على مستندات رسمية.

### 2.2 الحذف المنطقي (Soft Delete)
مفيش أي حركة مالية بتتحذف فعلياً. بدل كده:
- تتشال من المصفوفة الفعّالة (`vaultTx`)
- تتضاف لمصفوفة منفصلة (`deletedVaultTx`) مع: `deletedAt` (توقيت)، `deletedBy` (المستخدم)، `deletedReason` (السبب الموثّق)
- **القاعدة دي عامة على كل الكيانات المالية في البرنامج**، مش الخزينة بس

### 2.3 قفل الفترات المحاسبية
`isDateLocked(dateStr)` → `true` لو التاريخ ≤ `settings.vaultLockedThrough`. أي حركة في فترة مقفولة (بعد اعتماد قوائمها المالية) ممنوع تُضاف/تتعدّل/تتحذف.

### 2.4 توحيد قيد حوالات الشركات
حوالة الشركة بيبقى ليها **قيد خزينة واحد بس** بكامل المبلغ (مش قيد منفصل لكل متدرب) — لأن المبلغ بيتحصّل دفعة واحدة من الشركة بغض النظر عن توزيعه على المتدربين.

## 3. تمويل مخزون الحقائب (نموذج الأمانة) — module-bags.js

ده الجزء الأكثر تعقيداً في النظام المحاسبي، ولازم يتفهم كويس قبل أي إعادة بناء.

### 3.1 المبدأ الأساسي
**إيراد الحقائب مستبعد تماماً من دخل المركز** — الحقيبة "أمانة" بتتمر من خلال المركز للعميل، مش بيع فعلي للمركز.

### 3.2 إعادة احتساب دفتر التمويل من الصفر في كل مرة
`recalcBagFundLedger()` بتمشي على **كل** سجلات `bagStock` مرتبة بتاريخ الإنشاء، وتعيد بناء الرصيد بالكامل من البداية (مش تحديث تراكمي) — عشان تفضل صحيحة حتى لو اتحذف سجل قديم من النص.

القواعد لكل نوع سجل:

| نوع السجل | التأثير |
|---|---|
| **بدون `type`** (سجلات قديمة) | إضافة كمية ثابتة يدوياً، من غير تأثير على الرصيد المالي |
| **`manualQty`** (كمية مُدخلة يدوياً، من فاتورة شراء حقيقية) | الكمية تُعتمد كما هي حرفياً، وسعر الوحدة يُحسب من `amount / manualQty` (ما يتأثرش بسعر الحقيبة الحالي في الإعدادات لاحقاً) |
| **`withdraw`** (سحب) | `totalValue = bags×price + balance - amount` ثم `newBags = floor(totalValue/price)`، والفرق يتحدد وفقاً لذلك |
| **`issue`** (تسليم حقيبة لعميل) | ينقص عدد الحقائب بمقدار 1 بس، **بدون أي أثر مالي** (قيمتها اتحسبت وقت الإيداع مسبقاً) |
| **إيداع عادي** | `combined = balance + amount`، `addedBags = floor(combined/price)`، والباقي (`combined - addedBags×price`) يترحّل كرصيد للعملية الجاية — ده آلية "تجميع مبالغ جزئية لحد ما تكمّل حقيبة" |

### 3.3 حساب إجماليات المخزون
```
fundingQty = مجموع كميات كل السجلات الفعلية (باستثناء issue والمُعلَّقة)
spentBulk  = مجموع (qty × unitPrice) لنفس السجلات
issuedToClients = عدد العملاء اللي bagSource === 'stock' وغير موقوفين
purchasedQty = fundingQty - issuedToClients
```

### 3.4 السجلات "قيد الاعتماد"
سجل مسجَّل من موظف استقبال وينتظر اعتماد الأدمن — **لا يدخل أي إجمالي** (لا مخزون، لا رصيد، لا مصروف) لحد ما يُعتمد. نفس مبدأ الخزينة والدورات بالظبط.

## 4. حوالات الشركات — module-companies.js

### 4.1 إجمالي المخصص للحوالة
```
transferAllocatedTotal(t) = مجموع (courseValue + bagValue) لكل متدرب في الحوالة
```

### 4.2 حساب النصيب لكل متدرب (نموذج بسيط)
```
الحصة = المبلغ الكلي / عدد المتدربين   (لو التقسيم بالتساوي)
```
لكن فيه دعم لتقسيم حسب فئات مختلفة (مثلاً: مقيم بسعر، سعودي بسعر تاني) عبر "مجموعات" (`ctGroups`) — كل مجموعة ليها تصنيف وعدد وسعر منفصل.

### 4.3 مزامنة قيمة المتدرب مع شيت العملاء
قيمة الحوالة هي **المصدر الرسمي دائماً** — أي قيمة عميل مرتبط بحوالة شركة بتتاخد من الحوالة نفسها، مش العكس. النظام بيعيد المزامنة دي في كل تحميل (مش مرة واحدة) عشان يلحق أي حوالة لسه ما ترحّلتش.
