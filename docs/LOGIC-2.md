## 5. المعادلات المالية الأساسية للعميل (undo-redo.js)

الأساس اللي كل حاجة تانية (فواتير، تقارير، ZATCA) بتُبنى عليه:

```
bagAmount(c)     = c.bagSource === 'own' ? 0 : num(c.bagPrice)
                    // لو العميل جايب حقيبته الشخصية (own) = صفر. غير كده = سعر الحقيبة كامل
centerIncome(c)  = num(c.coursePrice) - num(c.discount)
                    // ده "إيراد المركز الحقيقي" — الحقيبة مش داخلة هنا أبداً (اتفقنا عليه في الجزء 1)
total(c)         = centerIncome(c) + bagAmount(c)
                    // الإجمالي المستحق على العميل (دورة + حقيبة لو مش own)

paidTotal(c):
  - لو العميل بدون clientId (رقم هوية)     → num(c.paid) + num(c.paid2)  [دفعتين تسجيل يدويتين]
  - لو العميل من حوالة شركة (companyTransferAllocated=true)
                                            → num(c.paid) + num(c.paid2)  [موثوق بالقيمة المُزامَنة من الحوالة مباشرة]
  - غير كده (عميل عادي له clientId)         → مجموع كل الحركات الواردة بنفس رقم الهوية في "الحركات المالية"
                                               ناقص أي مردودات مبيعات مرتبطة بنفس رقم الهوية
                                               (بحد أدنى صفر، ما ينزلش تحت الصفر)

remaining(c)     = max(0, total(c) - paidTotal(c))
```

**⚠️ حالة خاصة مهمة جداً**: عميل مُرحّل من حوالة شركة، مبلغه **مش موجود** كقيد منفصل في "الحركات المالية" بنفس رقم هويته (لتفادي تكرار المبلغ، لأنه أصلاً جزء من القيد الموحد الواحد للحوالة كلها — راجع قسم 2.4 في الجزء 1). فالنظام يثق مباشرة بحقل `paid`/`paid2` المُزامَن بدل ما يدور في الحركات المالية.

## 6. الفواتير — module-invoices.js

### 6.1 الترقيم الرسمي (نفس فلسفة ترقيم الخزينة)
```
formatInvoiceNo(n) = 'INV-' + n مبطّن بأصفار لـ 6 خانات   (مثال: INV-000482)

assignInvoiceNumber(client):
  1. لو العميل عنده رقم فاتورة بالفعل → رجّعه كما هو (رقم لا يتغيّر أبداً بعد التخصيص)
  2. احسب أعلى رقم مُستخدَم فعلياً بين كل العملاء
  3. الرقم الجديد = max(settings.nextInvoiceNo, أعلى_رقم_مستخدم + 1)
     // ده احتياط ضد اختلاف العداد عن الواقع بسبب استيراد بيانات قديمة أو تأخر مزامنة جهاز
  4. حدّث settings.nextInvoiceNo للرقم التالي واحفظ
```

### 6.2 الحذف المنطقي لفاتورة عميل
نفس مبدأ القسم 2.2 بالضبط: الرقم يتشال من العميل (`taxInvoiceNo = null`) لكن يُسجَّل في `deletedInvoices[]` مع السبب والتوقيت والمستخدم — **ولا يُعاد استخدامه أبداً**. الفاتورة الجاية للعميل نفسه هتاخد رقم جديد من العداد.

### 6.3 حساب إجمالي الفاتورة والضريبة
```
bagShown = bagAmount(c) > 0 AND paidTotal(c) >= (centerIncome(c) + bagAmount(c))
           // قيمة الحقيبة تظهر في الفاتورة فقط لو اتحصّلت بالكامل مع الدورة معاً — 
           // لو لسه ما اتحصّلتش كاملة، ما تظهرش في الفاتورة خالص

totalInclVat = centerIncome(c) + (bagShown ? bagAmount(c) : 0)
vat          = vatFromGross(totalInclVat)     // فك تضمين الضريبة (المبلغ المُدخل شامل الضريبة أصلاً)
netAmount    = totalInclVat - vat             // "القيمة الفعلية" بدون ضريبة
```

**قاعدة مهمة**: المبالغ المُدخلة في النظام (سعر الدورة، سعر الحقيبة) **شاملة الضريبة من البداية** — فبنستخرج الضريبة من جوّاها (فكّ تضمين)، مش بنضيفها فوق. لو حد غلط وضاف الضريبة فوق بدل الفك، النتيجة هتبقى غلط بحوالي 15% زيادة على كل فاتورة.

### 6.4 ZATCA — رمز الاستجابة السريعة (QR) — المرحلة الأولى
ترميز TLV (Tag-Length-Value) لخمس حقول إلزامية، بعدين Base64:

| Tag | الحقل |
|---|---|
| 1 | اسم البائع |
| 2 | الرقم الضريبي |
| 3 | الطابع الزمني (ISO) |
| 4 | الإجمالي شامل الضريبة (رقمين عشريين) |
| 5 | قيمة الضريبة (رقمين عشريين) |

**تفصيلة تقنية مهمة في ترميز الطول (Length)**: المواصفة بتتطلب BER-TLV. لو طول القيمة بالبايت أقل من 128 → بايت واحد للطول. لو 128 أو أكتر (زي اسم بائع طويل) → لازم **ترميز ممتد**: بايت أول = `0x80 | عدد_بايتات_الطول`، وبعده البايتات دي بترتيب big-endian. تجاهل الحالة دي بيكسر أي حقل أطول من 255 بايت (كان فيه باج قديم زي كده اتصلح).

> **ملاحظة**: البرنامج فيه كمان بداية ربط "فاتورة" (المرحلة الثانية الرسمية مع توقيع رقمي وسيرفر) في `zatcaSubmit`، لكن حالياً الفاتورة اللي بتتطبع من شيت العملاء **مقطوعة عمداً عن الإرسال للهيئة** (قرار عمل موثّق في الكود) — بقت "فاتورة مبسطة داخلية" برمز QR محلي بس، من غير اتصال بالسيرفر. القرار ده سمح للاستقبال يطبع الفاتورة قبل اعتماد الأدمن بأمان.

## 7. الإيرادات والمصروفات وقائمة الدخل — module-reports.js

### 7.1 توزيع الإيرادات حسب نوع الدورة
```
revenueBreakdown(from, to):
  لكل عميل غير ملغي (!c.cancelled) وتاريخه ضمن الفترة:
    اجمع centerIncome(c) تحت مفتاح نوع الدورة (courseType)
  // ملحوظة: bagAmount مش داخل في الإيراد هنا خالص — نفس مبدأ الأمانة
```

### 7.2 مردودات المبيعات
```
salesReturnsTotal(from, to):
  = مجموع حركات الخزينة (type='out', isReturn=true) ضمن الفترة
    باستثناء أي مردود لعميل "ملغي" أصلاً (لأن إيراده مستبعد بالفعل من revenueBreakdown،
    فخصم مردوده تاني هيعمل خصم مزدوج ويطلع صافي سالب غلط)
```

### 7.3 المصروفات
```
expenseBreakdown(from, to):
  = حركات الخزينة (type='out') ضمن الفترة، باستثناء:
    - حركات مرتبطة بمخزون الحقائب (bagStockRef) — دي مش مصروف تشغيلي، دي تمويل أمانة
    - المردودات (isReturn)
    - مسحوبات الشركاء (category === 'مسحوبات شركاء')
    - سداد/استلام قروض (isLoanTx)
  مُجمَّعة حسب التصنيف (category)
```

### 7.4 قائمة الدخل الكاملة (أساس الاستحقاق)
```
grossRevenue = مجموع كل revenueBreakdown
netRevenue   = grossRevenue - salesReturnsTotal
totalExpenseBase = مجموع كل expenseBreakdown
dep = مجموع قيود الإهلاك اليدوية (journal type='depreciation') ضمن الفترة
acc = مجموع قيود المصروف المستحق اليدوية (type='accrued') ضمن الفترة
rj  = مجموع قيود التسوية الأخرى اليدوية (type='readj') — بالسالب أو الموجب حسب طبيعتها

totalExpense = totalExpenseBase + dep + acc
netIncome    = netRevenue - totalExpense + rj
```

## 8. إقرار ضريبة القيمة المضافة — module-zatca.js

### 8.1 تجميع صفوف المبيعات (من مصدرين)
- فواتير الدورات (العملاء اللي عندهم `receiptActualValue > 0` وتاريخ إيصال ضمن الفترة)
- الفواتير اليدوية (`manualSalesInvoices` — فواتير مبيعات مسجّلة يدوياً، غير مرتبطة بعميل تدريبي، زي بيع خدمات إضافية)

### 8.2 حساب الإقرار الكامل
```
salesGross      = مجموع (شامل الضريبة) لكل صفوف المبيعات
outputVatGross  = مجموع ضريبة كل صفوف المبيعات
returnsGross    = مجموع مبالغ المردودات (شامل الضريبة)
returnsVat      = مجموع ضريبة المردودات

outputVat  = outputVatGross - returnsVat        // صافي ضريبة المخرجات بعد خصم المردودات
salesNet   = (salesGross - outputVatGross) - (returnsGross - returnsVat)   // صافي المبيعات بدون ضريبة

purchasesGross = مجموع (شامل الضريبة) لفواتير المشتريات ضمن الفترة
inputVat       = مجموع ضريبة المشتريات (input tax)
purchasesNet   = purchasesGross - inputVat

netVat = outputVat - inputVat
         // موجب = مستحق للهيئة (لازم يتدفع)
         // سالب = رصيد دائن لصالح المركز (يترحّل أو يُسترد)
```

جدول "مطابقة صناديق الإقرار الرسمي" (`renderZtVatBoxesTable`) بيرتب النتائج دي بالظبط بنفس ترتيب نموذج بوابة الهيئة (Box 1 مبيعات محلية 15%، Box 6 مشتريات محلية 15%، Box 11 الصافي) — الصناديق التانية (احتساب عكسي، نسبة صفر، صادرات، معفاة) موجودة في الجدول بقيمة صفر افتراضياً لأنها مش سيناريو مركز تدريب عادي، لكن الهيكل جاهز لو احتاج المركز يستخدمها يوماً.

### 8.3 الزكاة (تقديري)
```
وعاء الزكاة = max(0,
    حقوق الملكية (من الميزانية العمومية)
  + max(0, القروض طويلة الأجل)
  - max(0, صافي الأصول الثابتة)
  + إضافات يدوية
  - خصومات يدوية
)
الزكاة المستحقة = وعاء الزكاة × نسبة الزكاة (افتراضي 2.5%)
```
> ده حساب **تقديري** بيعتمد على قيم الميزانية العمومية + تعديلات يدوية بيدخلها المحاسب — مش حساب زكاة رسمي معتمد من هيئة الزكاة، والكود نفسه بيسميه "تقديري" صراحة.
